## 1. История ЭВМ

- **Ручной период (до компьютерной эры):** счётные палочки, пальцевый счёт, абак, позиционная система счисления. Позже появилось счётное устройство Леонардо да Винчи.
- **Механический этап (с начала XVII в.):** разностная машина Бэббиджа, арифмометр Однера.
- **Электромеханический этап:** машины Холлерита, основоположника счётно-перфорационного направления, и счётно-аналитические станции.
- **Современные ЭВМ (четыре поколения):**

| Поколение | Годы | Элементная база | Скорость и память | Ввод и вывод |
|---|---|---|---|---|
| 1 | 1940–59 | электронные лампы | 10–20 тыс. оп/с | перфокарты, перфоленты |
| 2 | 1960–69 | транзисторы | до 1 млн оп/с, 1 Мб | дисплей, клавиатура, диски, принтер; появились алгоритмические языки |
| 3 | 1970–79 | интегральные схемы | до 10 млн оп/с, до 10 Мб | клавиатура, графопостроитель, принтер |
| 4 | с 1980 | БИС (микроЭВМ) | до 100 млн оп/с, до 1 Гб | цифровой дисплей, клавиатура |

- **Пятое поколение:** ЭВМ, построенные по принципу человеческого мозга (всё, что может нейросеть).

## 2. Классификация ЭВМ

- **По принципу действия:** цифровые, аналоговые, гибридные.
- **По этапам создания:** от 50-х до 00-х годов. В 00-х это оптоэлектронные ЭВМ с массовым параллелизмом и нейроструктурой.
- **По назначению:** универсальные, проблемно-ориентированные, специализированные.
- **По размерам:** сверхбольшие, большие, малые, сверхмалые.

## 3. Архитектура и логические элементы

- **Структура** определяет состав средства на выбранном уровне детализации и описывает связи внутри него.
- **Архитектура** задаёт основные правила взаимодействия элементов и фиксирует только необходимые связи.
- **Логический элемент** реализует элементарную логическую функцию. По типу сигнала бывают импульсные, потенциальные и импульсно-потенциальные.
- **Порядок логических операций:** инверсия, конъюнкция, дизъюнкция, импликация, эквиваленция.
- **Схемы:** регистры, триггеры, сумматоры, мультиплексор, демультиплексор, шифратор.
- **Триггер** хранит состояние сколь угодно долго, на нём строится память.
  - Асинхронные триггеры меняют выход сразу вслед за входом.
  - Синхронные меняют состояние только при синхросигнале. Они делятся на статические и динамические.
  - Типы: RS, D, T, JK.
- **Регистр** принимает, хранит и передаёт информацию. Бывают накопительные и сдвиговые (однонаправленные или реверсивные).

## 4. Процессор

### Устройство управления (УУ)

Основные функции:

1. формирование адреса инструкции;
2. считывание инструкции из ОЗУ и хранение её на время выполнения;
3. дешифрация кода операции;
4. формирование управляющих сигналов;
5. считывание составляющих адресов операндов и формирование их полных адресов;
6. выборка операндов и выполнение над ними операции;
7. запись результатов в память;
8. формирование адреса следующей команды.

Блоки УУ:

- **Регистр команд** хранит код команды и адрес.
- **Дешифратор** выделяет из него код операции.
- **ПЗУ микропрограмм** хранит управляющие сигналы.
- **Узел формирования адреса** вычисляет полный адрес ячейки памяти.

### АЛУ

- принимает операнды из ОЗУ и регистров;
- выполняет арифметические и логические операции;
- передаёт результаты в регистры и ОЗУ;
- формирует признаки результата и записывает их в регистр состояния.

В состав АЛУ входят сумматор, регистры и схемы управления.

### Адресация памяти

Преобразование адресной информации об операнде в исполнительный адрес. Бывает прямой и косвенный.

### Системная шина

Быстрый канал связи процессора с памятью и периферией:

- **шина данных** передаёт данные;
- **адресная шина** передаёт адреса ячеек и идентификаторы устройств;
- **шина управления** передаёт управляющие сигналы.

### Архитектуры

- **Гарвардская:** программы и данные хранятся раздельно и читаются параллельно по отдельным шинам.
- **Классификация Флинна:** SISD (один поток команд и один данных), MISD, SIMD (системы с большим числом процессоров), MIMD.
- **x86:** самая распространённая в компьютерах и телефонах, с широким набором инструкций. Ограничение 4096 Мб в рукописи читается плохо.

## 5. Характеристики и быстродействие процессора

| Параметр | Что определяет |
|---|---|
| Тактовая частота (ГГц) | скорость выполнения одной операции; внутренняя влияет на обработку данных, внешняя на обращение к ОЗУ |
| Ядра и потоки | способность к многопоточности |
| Разрядность (x32/x64) | предельное число разрядов двоичного числа, с которым работает устройство |
| Техпроцесс | плотность и размер транзисторов |
| Кэш-память | объём быстрой памяти, сокращает обращения к ОЗУ |
| Сокет | разъём для подключения процессора |
| TDP | тепловыделение, которое должна отвести система охлаждения |
| Графическое ядро | встроенный блок для обработки графики |
| Связь с ОЗУ | скорость обмена данными |

**Индекс производительности** — единая оценка в баллах, показывающая эффективность работы компонентов компьютера.

**Основные задачи процессора:**

- работа с данными в ОП;
- обработка запросов от компонентов и устройств;
- временное хранение информации о программе и командах;
- передача результатов внешним устройствам;
- арифметические и логические операции.

## 6. Система команд (запись от 01.10.26)

### Пересылка данных

| Команда | Назначение |
|---|---|
| `move` | общая пересылка |
| `load` | загрузка в регистр процессора |
| `push` / `pop` | запись в стек / извлечение из стека |
| `movs` | строчная пересылка |
| `in` / `out` | ввод / вывод через устройство ввода-вывода |

К этой группе относится и обмен информацией.

### Арифметические

`add` (сумма), `sub` (разность), `mul` (умножение), `div` (деление). Работают с двоичными и двоично-десятичными кодами. Есть и команды с плавающей запятой.

### Одноадресные и сравнение

`clr` (очистка), `inc` (+1), `dec` (−1), `cmp` (сравнение), `tst` (проверка операнда), `bit` (проверка бита).

### Флаги

Биты регистра состояния процессора, выставляются по результату каждой команды. `sec` и `stc` устанавливают флаг, `clc` его очищает.

### Логические

`and`, `or`, `xor`, `not`. Принимают 1–2 входных операнда и формируют один выходной.

### Циклические сдвиги

Сдвигают биты кода по кругу. Флаг переноса может входить в кольцо или не входить.

### Переходы

Меняют обычный последовательный порядок выполнения (подпрограммы, циклы, ветвления).

- **Безусловные** (`jmp`, `branch`): переход происходит всегда, смещение задаётся операндом.
- **Условные:** при выполнении условия в счётчик команд загружается новое значение, иначе счётчик просто увеличивается. Условие проверяют через `cmp`.
- **Возврат:** `ret`, `rts` возвращают в точку вызова подпрограммы.
- **Прерывания:** `int` вызывает прерывание, `iret`, `rti` возвращают из него.
- При переходе с возвратом параметры процессора сохраняются в стеке.

## 7. C# (отдельная вставка)

```csharp
short c = Int16.MinValue;                     // -32768
short d = Int16.MaxValue;                     //  32767
string sc = c.ToString();                     // "-32768"

short f = Int16.Parse("-32768");              // ok
short g = Int16.Parse("-32769");              // ошибка: переполнение
short h = Int16.Parse("-32768a");             // ошибка: формат данных

bool bf = Int16.TryParse("-32768", out f);    // true
bool bg = Int16.TryParse("-32769", out g);    // false, g = 0
bool bh = Int16.TryParse("-32768a", out h);   // false, h = 0

int? a = b ?? -1;                             // a = b, если b != null, иначе -1
```

- **`ToString()`** преобразует число в строку.
- **`Parse()`** небезопасно преобразует строку в число и выдаёт ошибку при переполнении или неверном формате.
- **`TryParse()`** безопасно преобразует строку в число. Возвращает `bool`, при неудаче результат равен 0.
- **`int?`** допускает значение `null`. Такой тип можно использовать для проверки наличия данных внутри класса.
- **`??`** задаёт запасное значение при инициализации переменной.
- **`?.`** — условный доступ к члену объекта (`infoTimeData?.Hours`).

Пример класса из конспекта:

```csharp
class TimeDataStamp
{
    int _seconds;
    public TimeDataStamp() { _seconds = 0; }

    public int Hours
    {
        get { return _seconds / 3600; }
        set { _seconds = value * 3600; }
    }
}

TimeDataStamp infoTimeData = new TimeDataStamp();
infoTimeData.Hours = 2;
```
